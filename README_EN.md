# ORB-SLAM3 Dense ROS2 with OctoMap Converter

[English](README_EN.md) | [中文](README_CH.md)

This project provides ORB-SLAM3-based dense point cloud generation and OctoMap conversion. It supports converting dense point clouds generated by SLAM into OctoMap octree maps.

## Features

- **Dense point cloud generation**: Generate high-precision dense point clouds with ORB-SLAM3
- **Real-time OctoMap conversion**: Convert dense point clouds to OctoMap format in real time
- **PCD file conversion**: Convert existing PCD files to OctoMap
- **Configurable parameters**: Tune OctoMap resolution, maximum range, and other parameters

## System Requirements

- ROS 2 Humble Hawksbill
- C++17 or later
- PCL 1.15.0
- OctoMap
- OpenCV 4.9.0
- Eigen 3.3.7

## Installation

### 1. Install dependencies

```bash
# Install ROS 2 Humble if it is not installed yet.
# Reference: https://docs.ros.org/en/humble/Installation.html

# Install OctoMap and related dependencies.
sudo apt install ros-humble-octomap ros-humble-octomap-msgs ros-humble-octomap-server

# Install PCL dependencies.
sudo apt install libpcl-dev
```

### 2. Build the project

```bash
# Enter the workspace.
cd /home/ricky/WCR_ws

# Build the package.
colcon build --packages-select orbslam3_dense_ros2
```

## Run Guide

### Method 1: Generate OctoMap from ORB-SLAM3 dense point clouds in real time

1. **Start the ORB-SLAM3 dense SLAM node**:
   ```bash
   # Source the workspace.
   source /home/ricky/WCR_ws/install/setup.bash

   # Recommended: use the launch file to start RealSense, the ORB-SLAM3 dense node,
   # and OctoMap conversion together.
   ros2 launch orbslam3_dense_ros2 dense_mapping.launch.py
   ```

   Or start only the ORB-SLAM3 dense node:
   ```bash
   ros2 run orbslam3_dense_ros2 orb_slam3_main \
     /home/ricky/WCR_ws/dense_orbslam3/Vocabulary/ORBvoc.txt \
     /home/ricky/WCR_ws/dense_orbslam3/Examples/RGB-D/RealSense_D435i.yaml \
     true \
     /camera/camera/color/image_raw \
     /camera/camera/aligned_depth_to_color/image_raw \
     true
   ```

2. **Start the OctoMap conversion node**:
   ```bash
   # Open a new terminal and source the workspace.
   source /home/ricky/WCR_ws/install/setup.bash

   # Run the OctoMap conversion node.
   ros2 run orbslam3_dense_ros2 octomap_converter
   ```

3. **Visualize the OctoMap**:
   ```bash
   # Open a new terminal and source the workspace.
   source /home/ricky/WCR_ws/install/setup.bash

   # Start RViz2.
   ros2 run rviz2 rviz2
   ```
   In RViz2:
   - Add a `PointCloud2` display and set the topic to `/orb_slam3/dense_points` to view the dense point cloud
   - Add an `OccupancyGrid` display and set the topic to `/orb_slam3/octomap` to view the OctoMap

### Method 2: Play an RGB-D dataset for dense mapping

The new node `rgbd_dataset_dense_node` feeds TUM RGB-D datasets, or datasets with `rgb/depth` folders, into ORB-SLAM3 in timestamp order. Like the real-time camera node, it initializes `ORB_SLAM3::System(..., RGBD, use_viewer)`. When `use_viewer=true`, Pangolin can show sparse map points, current-frame feature points, and the camera frame. The node also publishes a dense point cloud with the same format:

| Topic | Type | Fields |
|-------|------|--------|
| /orb_slam3/dense_points | sensor_msgs/PointCloud2 | `x/y/z/rgb`, `frame_id=map` |

1. **TUM association-file mode**:
   ```bash
   source /home/ricky/WCR_ws/install/setup.bash

   ros2 run orbslam3_dense_ros2 rgbd_dataset_dense_node \
     /home/ricky/WCR_ws/dense_orbslam3/Vocabulary/ORBvoc.txt \
     /home/ricky/WCR_ws/dense_orbslam3/Examples/RGB-D/TUM1.yaml \
     /home/ricky/WCR_ws/dense_orbslam3/dataset/TUM-RGBD/rgbd_dataset_freiburg1_room \
     /home/ricky/WCR_ws/dense_orbslam3/Examples/RGB-D/associations/fr1_room.txt \
     true \
     realtime
   ```

   Equivalent named-argument form:
   ```bash
   ros2 run orbslam3_dense_ros2 rgbd_dataset_dense_node \
     --voc /home/ricky/WCR_ws/dense_orbslam3/Vocabulary/ORBvoc.txt \
     --param /home/ricky/WCR_ws/dense_orbslam3/Examples/RGB-D/TUM1.yaml \
     --tum /home/ricky/WCR_ws/dense_orbslam3/dataset/TUM-RGBD/rgbd_dataset_freiburg1_room:/home/ricky/WCR_ws/dense_orbslam3/Examples/RGB-D/associations/fr1_room.txt \
     --viewer true \
     --dense-mode realtime
   ```

2. **Plain folder mode**:
   The dataset root directory must contain `rgb/` and `depth/` subdirectories. Files are sorted by filename and paired frame by frame.
   ```bash
   ros2 run orbslam3_dense_ros2 rgbd_dataset_dense_node \
     --voc /home/ricky/WCR_ws/dense_orbslam3/Vocabulary/ORBvoc.txt \
     --param /home/ricky/WCR_ws/dense_orbslam3/Examples/RGB-D/TUM1.yaml \
     --root_dir /path/to/rgbd_dataset \
     --viewer true \
     --dense-mode realtime
   ```

3. **View dense point clouds and OctoMap together**:
   ```bash
   ros2 run orbslam3_dense_ros2 octomap_converter
   ```
   `octomap_converter` subscribes to `/orb_slam3/dense_points` by default. To subscribe to another point cloud topic:
   ```bash
   ros2 run orbslam3_dense_ros2 octomap_converter --ros-args \
     -p input_pointcloud_topic:=/your/pointcloud_topic
   ```

Dense mapping modes for the dataset node:

| Mode | Description |
|------|-------------|
| realtime | During playback, each newly discovered keyframe is sent into `PointCloudMappingRGBD`. This is suitable for viewing `/orb_slam3/dense_points` live in RViz. |
| deferred | After playback finishes, SLAM is shut down, then RGB-D images are reloaded and fused according to the optimized Atlas keyframes. This is closer to the logic in `rgbd_tum_dense.cc`. |
| both | Publish once in real time during playback, then rebuild the final dense map from Atlas keyframes after playback finishes. |

Common parameters:

| Parameter | Default | Description |
|-----------|---------|-------------|
| dense_build_mode | realtime | `realtime`, `deferred`, or `both` |
| dense_resolution | 0.01 | Dense point cloud voxel-filter resolution in meters |
| dense_mean_k | 50.0 | PCL statistical outlier removal MeanK |
| dense_std_thresh | 2.0 | PCL statistical outlier removal threshold |
| dense_unit | 5000.0 | Depth-unit conversion. TUM 16UC1 depth usually uses 5000. |
| dataset_fps | 30.0 | Playback FPS for folder mode or abnormal timestamps |
| playback_speed | 1.0 | Dataset playback speed. Set to `0.0` to process as fast as possible without waiting. |
| max_frames | -1 | Maximum number of frames to process. `-1` means unlimited. |
| keep_alive_after_finish | true | Keep the node, Pangolin, and RViz viewing state alive after dataset playback finishes |
| dense_pointcloud_topic | /orb_slam3/dense_points | Dense point cloud publishing topic |
| dense_publish_period_ms | 500 | Dense point cloud publishing period in milliseconds |
| deferred_timestamp_tolerance | 1e-4 | Timestamp tolerance for matching keyframes to original images in deferred mode |

### Method 3: Generate OctoMap from a PCD file

1. **Prepare a PCD file**:
   Make sure you have a PCD point cloud file, for example `/home/ricky/WCR_ws/dense_orbslam3/Examples/RGB-D/PointCloudMapping_RGBD.pcd`.

2. **Run the PCD-to-OctoMap conversion node**:
   ```bash
   # Source the workspace.
   source /home/ricky/WCR_ws/install/setup.bash

   # Run the PCD-to-OctoMap conversion node.
   ros2 run orbslam3_dense_ros2 pcd_to_octomap_node --ros-args -p pcd_file:=/home/ricky/WCR_ws/dense_orbslam3/Examples/RGB-D/PointCloudMapping_RGBD.pcd
   ```
   ```bash
   # Run RViz2 locally.
   rviz2
   ```

3. **Visualize the OctoMap**:
   As above, add an `OccupancyGrid` display in RViz2 and set the topic to `/orb_slam3/octomap`.

## Parameter Configuration

### ORB-SLAM3 dense node parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| dense_build_mode | deferred | Dense mapping mode: `deferred` generates the PCD from optimized Atlas keyframes on exit; `realtime` inserts keyframes and publishes point clouds in real time; `both` does both |
| dense_resolution | 0.008 | Dense point cloud voxel-filter resolution in meters |
| dense_mean_k | 15.0 | PCL statistical outlier removal MeanK |
| dense_std_thresh | 3.0 | PCL statistical outlier removal threshold |
| dense_publish_period_ms | 300 | Real-time point cloud publishing period in milliseconds |
| dense_pointcloud_topic | /orb_slam3/dense_points | Dense point cloud publishing topic |

### RealSense launch parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| initial_reset | true | Reset the RealSense device before starting the camera node. Useful when the camera is partially suspended. |
| emitter_enabled | 1 | Enable the depth module IR emitter. In RealSense ROS this parameter is an integer enum. |
| color_profile | 848x480x30 | Color image resolution and frame rate |
| depth_profile | 848x480x30 | Depth image resolution and frame rate |

### OctoMap conversion node parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| input_pointcloud_topic | /orb_slam3/dense_points | Input dense point cloud topic |
| resolution | 0.05 | OctoMap resolution in meters |
| max_range | 5.0 | Maximum point cloud range in meters |
| color | true | Whether to use colored OctoMap |

### PCD-to-OctoMap node parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| pcd_file | - | PCD file path. This must be specified. |
| resolution | 0.05 | OctoMap resolution in meters |
| max_range | 5.0 | Maximum point cloud range in meters |
| color | true | Whether to use colored OctoMap |

## Topics

| Topic | Type | Description |
|-------|------|-------------|
| /orb_slam3/dense_points | sensor_msgs/PointCloud2 | Dense point cloud generated by ORB-SLAM3 |
| /orb_slam3/octomap | octomap_msgs/Octomap | Converted OctoMap |

## Troubleshooting

1. **Build errors**:
   - Make sure all dependencies are installed correctly
   - Check the path configuration in `CMakeLists.txt`

2. **Runtime errors**:
   - Check whether the ROS 2 environment variables are set correctly
   - Make sure the sensor driver is installed correctly, such as the RealSense camera driver
   - Check whether the PCD file path is correct

3. **OctoMap display issues**:
   - In RViz2, make sure the correct reference frame is selected, usually `map` or `base_link`
   - Adjust the OctoMap resolution and maximum range parameters

## Notes

- OctoMap resolution affects map accuracy and memory usage. Adjust it according to your actual needs.
- The maximum range parameter should match the environment size to avoid processing too much point cloud data.
- For large environments, a lower resolution is recommended to reduce computational load.
